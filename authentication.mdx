## API Key Authentication

API key authentication is the simplest method for authenticating requests to the Sendoh Cheung API. This approach is ideal for server-side applications and automated processes.

<CodeGroup tabs="JavaScript,Python">
  ```javascript
const apiKey = 'your-api-key';
const response = await fetch('/api/repositories', {
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  }
});
const data = await response.json();
  ```
  ```python
import requests

api_key = 'your-api-key'
headers = {
    'Authorization': f'Bearer {api_key}',
    'Content-Type': 'application/json'
}
response = requests.get('/api/repositories', headers=headers)
data = response.json()
  ```
</CodeGroup>

<Callout kind="info">
  Keep your API keys secure and never expose them in client-side code or public repositories.
</Callout>

## OAuth 2.0 Implementation

For applications requiring user-specific access, OAuth 2.0 provides a secure, standardized way to handle authentication and authorization.

<Expandable title="OAuth Flow Details" default-open="false">
  The OAuth 2.0 implementation in Sendoh Cheung follows the authorization code grant flow. First, redirect users to our authorization endpoint, then exchange the authorization code for access and refresh tokens.
</Expandable>

<ExpandableGroup>
  <Expandable title="Authorization Code Flow" default-open="true">
    This is the most secure OAuth flow for web applications that can securely store client secrets.
  </Expandable>
  <Expandable title="Implicit Flow" default-open="false">
    Suitable for single-page applications where client secrets cannot be stored securely.
  </Expandable>
  <Expandable title="Client Credentials Flow" default-open="false">
    Used for machine-to-machine authentication without user context.
  </Expandable>
</ExpandableGroup>

## Error Handling

Authentication errors can occur for various reasons. Proper error handling ensures a smooth user experience and helps with debugging authentication issues.

| Error Code | Description | Resolution |
|------------|-------------|------------|
| `401` | Invalid or expired token | Refresh token or re-authenticate |
| `403` | Insufficient permissions | Check token scopes and user roles |
| `429` | Rate limit exceeded | Implement backoff and retry logic |

<Callout kind="alert">
  Always implement proper error handling for authentication failures to provide clear feedback to users.
</Callout>

## Security Best Practices

Following security best practices helps protect your application and users from potential vulnerabilities. Sendoh Cheung recommends several key practices for secure authentication implementation.

- Use HTTPS for all API communications
- Implement token rotation and expiration
- Validate token signatures and claims
- Limit token scope to minimum required permissions
- Monitor authentication attempts for suspicious activity
